# Desktop Todo

一款常驻 Windows 桌面的待办卡片。首次打开可直接在本机记任务，也可连接 Nextcloud Tasks 在多台设备间同步。

## 它能做什么

- 点击主页的衣服图标，选择松墨工坊、雾海玻璃、杏仁纸笺、午夜终端、山茶花园或素色画布。素色画布提供自定义调色盘。
- 所有皮肤共用「背景不透明度」（25%–100%）。单击或拖动滑轨即可调整，切换皮肤和重启后都会保留该数值。升级时沿用原先所选皮肤的不透明度。
- 卡片字体默认跟随皮肤。杏仁纸笺使用 B「书页宋体」，山茶花园使用 C「手记楷体」，其余皮肤使用 A「清润黑体」。展开换肤面板里的「字体」可选择本机字体，换肤时保留手动选择。点「跟随皮肤」可恢复自动搭配。
- 标题栏的窗口位置按钮可选「桌面小工具」「普通窗口」「始终置顶」。默认的桌面小工具模式用于按 Win+D 显示桌面时继续查看和编辑待办。
- 任务增删改、勾选完成、右键设优先级（红高 / 橙中 / 蓝低）
- 与 Nextcloud Tasks 双向同步，添加 / 编辑 / 完成 / 删除 / 优先级变更立即写回服务器
- 不在任务栏显示按钮，只在右下角系统托盘常驻图标；「×」只隐藏窗口，不会结束程序
- **自动检测更新**：静默检查、只点亮一个角标，点一下即可完成下载与重启（见下文）

## 快速开始（推荐：下载 Release）

### 1. 下载并解压

到 [Releases 页面](https://github.com/lingting0/desktop-todo-wpf/releases/latest) 下载最新的 `DesktopTodo-vX.Y.Z-win-x64.zip`（**v1.1.0 及以上**才带自动更新），解压到任意普通文件夹（不要放进需要管理员权限的目录，例如 `C:\Program Files`）。

**解压即用，没有安装向导**：双击 `DesktopTodo.exe` 即可。

### 2. 装一次运行时

Windows 不自带 .NET 8，需要先安装 [**.NET 8 Desktop Runtime**](https://dotnet.microsoft.com/download/dotnet/8.0)。装一次即可，之后升级程序不用重装。

> 如果双击 exe 没反应或提示缺少运行时，基本都是这一步没做。

### 3. 选择任务存储

首次打开直接输入即可。本机清单随每次修改保存到 `%LOCALAPPDATA%\DesktopTodo\tasks.json`。已有 Nextcloud 配置的用户沿用原日历。在设置中切换「仅在本机记录任务」可往返两份独立的清单。本机任务不会自动上传。

启用 Nextcloud 的步骤如下。

1. 点标题栏的 **⚙（设置）**，取消「仅在本机记录任务」
2. 填写 **Nextcloud URL**、**用户名**、**应用密码**（密码框为遮蔽输入）
3. 点 **「测试连接」**——用当前填写的值实际连一次服务器，返回日历名与任务数；此步不落盘、不影响现有连接
4. 成功后点 **「保存」**

保存后**设置立即生效**：自动重建同步连接、按新间隔重置定时器并重新拉取任务，**不用重启程序**。

应用密码在 Nextcloud 网页端生成：**设置 → 安全 → 设备与会话 → 创建新应用密码**，不要填账号登录密码。

### 4. 日常使用

- 「×」或「─」：隐藏窗口，程序继续在后台同步
- 双击托盘图标（或右键「显示/隐藏」）：把卡片叫回来
- 右键托盘 →「退出」：**唯一**真正结束进程的方式

本地工作版本的功能记录见 [变更记录](CHANGELOG.md)。

|---|---|
| 操作系统 | Windows（x64） |

## 发行包里有什么

| 文件 | 作用 |
|---|---|
| `DesktopTodo.exe` | 程序入口，双击运行 |
| `DesktopTodo.dll` / `DesktopTodo.deps.json` / `DesktopTodo.runtimeconfig.json` | 运行必需 |
| `ToDoIcon.ico` / `ToDoIcon.png` | 托盘与窗口图标 |
| `config.example.json` | 配置模板，全是占位值，**不含任何凭据** |
| `README.md` | 本说明 |

**发行包不含**：`config.json`（真实运行配置）、任何密码或密钥、调试符号 `.pdb`。程序会在 exe 同目录自行维护 `config.json`，请勿把含真实服务器地址的配置打包分发。

## 设置项

| 项 | 说明 |
|---|---|
| Nextcloud URL | 例：`https://nc.example.com:8443/remote.php/dav/` |
| 用户名 | Nextcloud 账号名 |
| 应用密码 | 在 Nextcloud「设置 → 安全 → 设备与会话」生成；**保存在 Windows 凭据管理器** |
| 日历名称 | 按名称选用支持 VTODO 的日历；留空时回退到任务数最多的日历 |
| 同步间隔（秒） | 最小 30；保存后立即按新间隔重建定时器 |
| 自签证书 SHA-256 指纹 | 可选。留空 = 系统严格校验；填入后只信任该指纹对应的证书 |
| 开机自启 | 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| 代理地址 | 用于 GitHub 更新检查；留空 = 走系统代理。大部分用户需要代理才能访问 GitHub |

## 凭据与隐私

- 应用密码存放在 **Windows 凭据管理器**（控制面板 → 凭据管理器 → Windows 凭据，目标名 `DesktopTodo/Nextcloud/...`），**不写入 `config.json`，也不进入发行包**。`config.json` 只保存 URL、用户名和界面偏好。
- 旧版配置里若还带 `app_password`，新版启动时会把它迁移到凭据管理器，成功后从 JSON 中删除。由于该密码曾以明文出现在多处，**迁移后仍建议到 Nextcloud 后台吊销并重新生成**。
- 未处理异常写入 `%LOCALAPPDATA%\DesktopTodo\error.log`，界面只显示简短提示，不弹完整堆栈。

### 关于 TLS 与 http

| 场景 | 行为 |
|---|---|
| `https` + 有效证书 | 系统严格校验，正常连接 |
| `https` + 自签 / 无效证书 | 默认**拒绝**；在设置里填入该证书 SHA-256 指纹后才信任，且只信任这一张（证书固定） |
| `http://` | 不走 TLS，**可以正常使用**，但应用密码会明文经网络传输，仅建议在内网可信环境临时使用 |

证书指纹可在浏览器查看证书详细信息 →「指纹 (SHA-256)」，填入时去掉冒号与空格。

## 自动更新（低打扰）

从 **v1.1.0** 起，程序会自己检查 GitHub Releases 上的新版本。设计目标是「有提醒、不打扰、点一下就更新」。

### 什么时候检查

| 时机 | 行为 |
|---|---|
| 启动 8 秒后 | 静默检查一次 |
| 之后每 6 小时 | 复查一次（内部按 24 小时节流，实际每天最多一次） |
| 网络不通 / API 失败 / 限流 | **完全静默**：不弹窗、不写状态栏、不影响待办同步 |
| 托盘右键「检查更新」 | 手动立即检查，明确告知「已是最新版本」或打开更新窗口 |

检查只读取本仓库的公开 Release 元数据，**不上传任何数据**；也不依赖 Nextcloud 是否可连。

### 有新版本时怎么提醒

**不弹窗、不弹气泡、不抢焦点。** 只做三处被动可见的提示：

- 标题栏出现橙色 **⬆** 角标（悬停显示版本号）
- 托盘右键菜单多出「更新到 vX.Y.Z」，托盘图标提示文字也带上版本号
- 状态栏显示一行「发现新版本…」，**同一个版本只显示一次**

点 **⬆** 或托盘的「更新到…」才会打开一个非模态窗口：

| 按钮 | 效果 |
|---|---|
| **立即更新** | 一键完成 下载 → 校验 → 退出 → 替换 → 自动重启，全程不用再点 |
| 稍后提醒 | 延后 **3 天**，期间角标与菜单项都收起 |
| 忽略此版本 | 这个版本以后不再提醒；**之后发布的新版本仍会提醒** |
| 关闭 | 什么都不改，角标仍在，想更新随时点 |

### 一键更新做了什么

1. 从 GitHub Release 下载 `DesktopTodo-vX.Y.Z-win-x64.zip`，窗口内显示进度
2. 若 Release 同时提供 `.sha256` 资产则校验 SHA-256；否则校验 zip 完整性与必需文件
3. 备份当前程序文件到 `%LOCALAPPDATA%\DesktopTodo\updates\backup-*`
4. 结束当前进程（这一步是真正的退出，不是「×」的隐藏），由暂存目录里的新 exe 完成替换
5. 自动启动新版本

**`config.json`、窗口位置、主题和 Windows 凭据管理器里的应用密码全部原样保留**——发行包不含 `config.json`，替换时也会主动跳过它。

安全约束：只接受 https 且来自 `github.com` / `*.githubusercontent.com` 的地址；解压防路径穿越；缺 `DesktopTodo.exe` / `.dll` / `.runtimeconfig.json` 任一个即中止；**拒绝降级**到比当前程序更旧的版本。更新日志在 `%LOCALAPPDATA%\DesktopTodo\update.log`。

### 自己控制

`config.json` 里可改（都是本机偏好，不会进仓库）：

| 字段 | 说明 |
|---|---|
| `update_check_enabled` | `false` = 关掉后台自动检查，仍可从托盘手动检查 |
| `update_last_check_unix` | 上次检查的 UTC Unix 秒，用于 24 小时节流 |
| `update_snooze_until_unix` | 「稍后提醒」截止时间 |
| `update_ignored_version` | 被忽略的版本号 |
| `update_notified_version` | 已提示过的版本，避免重复写状态栏 |

### ⚠️ 首次需要手动升级一次

**v1.0.0 及更早的版本没有更新功能**，不会自己跳到 v1.1.0。请先到 Releases 下载一次 v1.1.0 的 zip 覆盖原目录（配置不会丢），**之后**发布的版本才能自动提醒与一键更新。这是自动更新功能的固有限制：第一版更新器只能从下一版开始生效。

验收整套流程可用命令行 `DesktopTodo.exe --pretend-version 1.0.0` 把当前版本伪装成旧版启动，程序会立即检查并打开更新窗口（仅用于验收，正常启动不要带此参数）。

## 同步行为与已知限制

- 定时全量拉取；本地的添加 / 编辑 / 完成 / 删除 / 优先级变更立即写回服务器。
- 使用 **ETag + `If-Match` / `If-None-Match`** 做乐观并发；遇到 412 会提示「已被其他设备修改」，不会静默覆盖。
- 写回时以服务端原始 VTODO 为底稿，只替换本程序管理的字段，保留 `DESCRIPTION`、`CATEGORIES`、`DUE`、`X-*` 等未知属性。
- 写操作失败会在状态栏提示，任务不会被静默隐藏或丢弃。
- **已知限制**：目前没有离线队列，断网时列表为空且写操作会提示失败；恢复后下一次定时同步会拉取最新数据。

## 常见问题

| 现象 | 处理 |
|---|---|
| 双击 exe 没反应 | 先装 .NET 8 Desktop Runtime |
| 「测试连接」提示认证失败 | 检查 URL、用户名、应用密码；确认用的是**应用密码**而非登录密码 |
| 自签证书连不上 | 在设置里填证书 SHA-256 指纹；不要留空硬连 |
| 用 http 时提示警告 | 属预期：能连，但凭据明文传输，建议改 https |
| 点「×」后程序还在 | 设计如此，托盘图标还在；要彻底结束请右键托盘 →「退出」 |
| 找不到窗口 | 双击托盘图标，或右键 →「显示/隐藏」 |
| 想换账号 / 重置配置 | 设置页改后保存即可；如需清空凭据，到 Windows 凭据管理器删掉 `DesktopTodo/Nextcloud/...` 条目 |
| 改了设置没生效 | 当前版本保存即生效；若仍异常，用托盘退出后重新打开 |
| 不想被提醒更新 | 更新窗口点「忽略此版本」，或把 `config.json` 的 `update_check_enabled` 设为 `false` |
| 更新中途失败 | 旧版本文件仍在，可直接重新运行；详情见 `%LOCALAPPDATA%\DesktopTodo\update.log`，必要时用 `updates\backup-*` 还原 |
| 点了「立即更新」后程序消失 | 属预期：正在替换文件并重启，几秒后会自动回来 |

## 从源码构建

需要 **.NET 8 SDK**，在仓库根目录运行 `build.bat`：

- 先清空旧的二进制文件（保留 `config.json`），再 `dotnet publish`
- 逐步检查返回码，失败时不再打印成功信息
- 输出**不包含 `config.json`**；脚本优先使用用户级 SDK（`%USERPROFILE%\.dotnet\dotnet.exe`，无管理员权限时的安装位置），否则用 PATH 中的 `dotnet`
- `build.bat --no-pause` 可用于自动化构建

请勿手工把 `config.json` 放进 `publish` 目录，也不要把含凭据的文件打包分发。

### 发布 Release（维护者）

`build.bat` 只生成本地 `publish`。要发布到 GitHub Releases，在仓库根目录运行：

```text
python make-release.py
```

脚本会读取 `DesktopTodo.csproj` 里的 `<Version>`，做一次**不带调试符号**的干净构建、逐个文件扫描隐私、生成：

- `dist/DesktopTodo-vX.Y.Z-win-x64.zip`
- `dist/DesktopTodo-vX.Y.Z-win-x64.zip.sha256`

**两个文件必须一起上传到 tag 为 `vX.Y.Z` 的 Release**，程序靠它们完成校验与一键更新。`dist/` 与 `.release-build/` 已被 `.gitignore` 排除。发版前记得同步递增 `<Version>` 与 Release tag。
